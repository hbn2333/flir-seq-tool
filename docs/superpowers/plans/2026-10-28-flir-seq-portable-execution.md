## 验证结果（2026-10-28）

完整回归使用隔离 Python、包内 FFmpeg 9.0.2：**755 passed，2 skipped**，耗时 691.84 秒。跳过项为 Windows 符号链接权限不足。随后新增/复验运行目录、启动路由和诊断报告保护测试：**9 passed**。诊断的报告和图像输出同样拒绝写入源文件/raw。源码模式旧 FFmpeg 4.3.1 编码器定向测试：**6 passed**。锁定环境中的 Matplotlib 3.10.3 与新版 pyparsing 发出弃用提示，不影响本轮测试。

第一次冻结诊断发现 FFmpeg 9 删除 `-vsync`，真实编码/完整解码测试复现后，改为能力检测：新版本使用 `fps_mode passthrough`，旧版保留 `vsync 0`。两种编码器分别验证。

只读审查发现并修复三个问题：重复构建清空旧包、PyInstaller 自动 hook 早于入口创建系统临时目录、清单无法追溯 dirty 源码/包含自身旧哈希。最终 spec 的自定义 hook 位于自动 Matplotlib hook 之前；后者的临时目录也归包内。早期试构建的启动隔离并不完整，最终包已修复；没有修改既有外部安装或系统配置。

在项目 `.packaging/acceptance-r3 中文 路径` 复制完整软件包，工作目录不同于 EXE 目录；PATH 仅含 Windows/System32 和 Windows，移除 PYTHONPATH、PYTHONHOME、FLIRFILESDKDIR，实际冻结诊断 **passed**：

- 临时目录和真实 SQLite 均在该包的 `cache/tmp`。
- SDK 第 10 帧为 640×480；最小值 22.148513793945312 °C、最大值 42.14434051513672 °C、均值 25.281801223754883 °C、时间 `2026-08-28T09:26:37.434000`，与源码读取结果完全一致。
- −2.3° 变换与 ROI 统计、Process/Measure 离屏绘图成功。
- 原生五帧 SEQ 导出后重新打开成功；MP4 spawn 工作进程、编码、全部帧解码验证及编码取消成功。
- Python、fnv、VC++、Tcl/Tk DLL 的加载路径来自复制后的包；系统基础 DLL 来自 Windows。无需依赖原 Python 或 SDK 安装目录。
- 使用 computer-use 技能，以 `view <最小SEQ>` 参数实际打开 TkAgg 窗口、点击切换到 Measure、关闭窗口，退出码 0。自动化未能定位隐藏根窗口拥有的原生选文件框，因此“双击选择/取消、拖入文件”仍需人工验收，不能以路由单元测试代替。
