## 实现细节与计划调整

输出为 H.264/libx264、CRF 18、medium、yuv420p、30 fps、1920×1080，无音轨。输入 RGB 通过管道流式送入；只缓存当前变换矩阵与当前 RGB。允许保留所选范围的时间戳，未加载整个温度序列。

时间映射使用整数微秒比较，避免边界处浮点误差。单帧为 30 张相同画面；多帧保留末帧。图像使用现有双线性空间变换，时间方向只选帧或重复帧。

编码模块与 GUI controller 从任务模块拆出；另增 `video_process.py` 管理 Windows 进程树。父进程持有 kill-on-close Job Object，工作进程必须完成归属登记后才能启动预检，FFmpeg 继承该进程树归属。

临时文件改由父进程在用户确认后独占创建，并将路径传给 worker。这样即使 worker 异常退出，父进程仍知道自己拥有的精确临时路径并能清理。预检和取消另存为不会创建视频。

完整解码使用 FFmpeg framehash 流，逐条核验实际解码尺寸、时间基与帧数，不依赖 ffprobe。复核源身份、源大小/mtime 和目标快照后原子替换。

按用户选择在本会话顺序实现；另安排一次只读代码审查。前两项合并为一个提交，后续模块验证后合并为第二个提交，未为每一个计划小项单独提交。

## 测试过程

- 新增时间/渲染/编码/请求/后台任务/controller 测试均在模块或接口缺失时先运行，记录预期失败，再实现。
- 对话框新增测试先得到 9 项预期失败，补实现后与旧对话框测试共同通过。
- UI 新增 MP4 confirmed-range/busy/cancel/close 测试先因缺少参数失败，接入后通过。
- 阻塞编码器测试实际启动不读取 stdin 且大量写 stderr 的辅助进程，验证取消解除阻塞、诊断最多 64 KiB、线程及子进程回收。
- Windows 进程树测试实际启动忽略取消的 worker 及其子进程；强制取消后同时检查两者退出。发现无结果终态将取消误报失败，已补回归并修复。
- 查看器相关回归初次为 156 passed / 1 failed（333.29 s）。失败源于旧 UI 生命周期测试替身未包含新增的 video_controller；同步接口后定向测试通过。
- 最近定向集合：75 passed（9.73 s）。真实最小 SEQ 集成集合：3 passed（12.53 s）。编码器、真实视频完整解码、末帧比较、源只读检查均实际执行，未用 skip 替代。
- 第一次完整回归：745 passed、2 skipped，698.36 s。跳过项是 Windows 未授予符号链接创建权限（WinError 1314）。
- 只读审查发现两处 P2 消息竞态：队列满时 ready/result 超时丢失；worker 在首次排空后退出时，已发送的结果可能被误判缺失。两项先添加失败复现测试，再分别改为控制消息可靠重试，以及观察退出后再次排空。
- 修复后的后台任务、controller 和真实 SEQ 集合：12 passed（18.34 s）。审查复核了修复，并在 64 KiB、1 MB、16 MB 消息下探测强制退出，没有复现队列阻塞。
- 后续故障注入复现了 worker 被终止时遗留共享 Event 锁导致 poll 阻塞。补失败测试后改为在 worker 死亡后读取父进程 cancel_time，已请求取消时不重复设置事件，close 不再对死进程调用 cancel。审查复核未发现该修复的具体剩余问题；最新后台任务/controller/真实 SEQ 集合为 13 passed（19.36 s）。
- 中间一次完整回归为修复上述边界而主动中断，不计作通过。
- 最终完整回归：`python -m pytest -q -rs -p no:cacheprovider --tb=short`，748 passed、2 skipped，649.08 s；无失败。两个 skip 均为前述 WinError 1314，真实 MP4/SDK 测试全部执行。
- 合并 main 后再次验证 MP4 全部专用单测与最小真实 SEQ 集成：46 passed（24.03 s）；源代码与完整回归时一致，后续仅更新文档和示例资源。
