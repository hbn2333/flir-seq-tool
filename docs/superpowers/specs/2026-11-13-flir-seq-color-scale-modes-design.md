采用两个模式，把自动与手动值都放入固定模式。拆成“自动固定、手动固定、逐帧自适应”三个模式会增加切换。边浏览边扩大温标无法保证未访问帧得到覆盖，也会让结果依赖浏览顺序。

Process 的候选范围拖动仅预览端点，Confirm 后才改变统计时间范围。矩形 ROI 的位置、勾选和高度分区都不影响图像温标的统计区域。

## 3. 数值定义

设已确认原始帧范围为 $[a,b]$，已应用的固定图像变换为 $G$。由官方 SDK 读取帧的摄氏温度矩阵 $X_i$，得到显示矩阵 $Y_i=G(X_i)$。有效温度集合为 $V_i=\{Y_i(p)\mid Y_i(p)\text{ 为有限数}\}$。

固定自动范围为

$$v_{min}=\min_{i=a,\ldots,b}\min V_i,\qquad v_{max}=\max_{i=a,\ldots,b}\max V_i.$$

逐帧范围对当前帧单独计算 $\min V_i$ 和 $\max V_i$。全局扫描逐帧读取并变换，累计两个极值，覆盖范围内的每一帧。MP4 的显示抽帧规则不参与全局范围统计。

排除 NaN、正负 Inf 和变换产生的无效背景。有效温度不再按百分位裁掉，不另加温度阈值、坏点推断、平滑或额外插值。旋转继续使用现有的双线性温度变换。

有限温度全部相同为 $T$ 时，显示范围扩展为 $[T-0.5,T+0.5]$ °C。某帧没有有效温度时，扫描记录该帧并继续；只要其他帧存在有效温度，仍可形成完整扫描结果。全部帧均无有效温度时，扫描失败并提示原因。

逐帧模式遇到全无效帧时，显示无有效温度提示，并沿用最近一次有效显示范围。新文件尚无有效范围时暂用 0～1 °C，状态明确标记范围未建立。该占位值不得被标记为自动完成结果。

界面刻度采用便于阅读的数字格式，配置与导出快照保留浮点数值的完整精度。自动结果的显示格式不应向内缩小实际生效范围。手动输入必须为有限数，且最低值严格小于最高值；无效输入保留最后有效设置并显示错误。

## 4. 共用交互与状态

Process 和 Measure 共用同一份温标设置，在图像区域附近放置紧凑的一组控件。

- 两个互斥模式按钮 `Fixed`、`Per frame`，选中状态使用现有蓝色主题。
- 两个摄氏度输入框 `Min (°C)`、`Max (°C)`。
- 固定模式使用 `Apply` 和 `Auto range`。
- 显示自动扫描进度、取消入口以及温标状态。

各模式行为如下。

| 状态 | 输入框 | 生效范围与操作 |
| --- | --- | --- |
| Fixed / Auto ready | 可编辑，初值为完整扫描结果 | 全部帧使用相同自动上下限 |
| Fixed / Manual | 可编辑 | Apply 原子提交两个值，全部帧使用同一手动范围 |
| Fixed / Scanning | 可编辑 | 显示进度；尚无已完成范围时按当前帧临时显示并明确标记 |
| Fixed / Cancelled 或 Failed | 可编辑 | 保留最近已完成范围，或继续使用明确标记的逐帧临时范围；Auto range 可重试 |
| Per frame | 显示当前帧范围，禁用编辑 | 每帧自动更新 colorbar |

固定模式已有完成范围，再主动请求扫描时，完成前沿用该范围；新扫描成功后一次替换。确认了新时间范围或 Apply 了新变换后，旧自动结果标记为不匹配，在完整新结果到达前采用带状态说明的逐帧临时范围。

手动值在确认范围、修改变换、切换页面和来回切换温标模式后持续保留。用户点击 Auto range 才返回自动固定策略。切换到 Per frame 会记住固定模式原先是自动还是手动，以及相应固定值；切回 Fixed 后按这个记忆恢复。

输入框的未 Apply 草稿与生效值分开保存。扫描完成和切帧可以更新实际温标及状态，正在编辑的文本持续保留，并显示待应用提示。切换到 Per frame 时暂存草稿并显示当前帧范围，返回 Fixed 时恢复草稿。Auto range 是明确的放弃输入草稿操作，随后填入匹配的自动结果或显示计算中状态。配置只保存已生效设置；切换文件时，未应用草稿纳入待处理输入，用户先应用或放弃，再继续现有切源流程。

编辑变换草稿期间冻结进入编辑时的实际温标，给角度和裁剪预览提供一致的颜色参照。Apply 后按新空间范围执行对应模式，Cancel 后恢复进入编辑前的设置。草稿操作不启动完整扫描。

更改温标使显示设置变为待保存状态，并使依赖旧显示设置的导出确认失效。逐帧浏览、扫描进度和自适应派生上下限属于运行状态。完成自动扫描形成新的可保存固定值时，显示设置随之更新。现有 ROI 统计与高度结果仍按原温度矩阵和几何范围判断有效性。

布局沿用现有字体和主题，兼容 Process、变换编辑与 Measure 页面，并在最小支持窗口及已有 DPI 检查中验证文字、控件和色条互不遮挡。原有温标之外的布局改动限定为容纳这些控件所需的调整。

## 5. 后台扫描与大文件

温标扫描使用独立只读 reader，逐帧温度矩阵在当前迭代结束后释放。主窗口 reader 与扫描 reader 分开使用。内存保持为少量帧、变换映射及常数规模的汇总结果。

请求在启动时冻结以下输入。

- 当前源文件身份，沿用 SourceIdentity 和已有文件变化核验。
- 已确认的原始首尾帧号。
- 已应用变换的指纹。
- 统计算法版本 `finite_minmax_v1`。
- 会话身份和任务代次。

主线程通过定时器读取进度和结果，并在主线程更新 Matplotlib artist。工作线程只读取、变换和累计数据。完整扫描和逐帧自适应共享有限温度范围函数。

默认自动固定在打开文件后启动后台扫描。确认范围或 Apply 变换后，如果固定策略为自动，则取消旧请求并调度新请求；逐帧模式下延迟到需要恢复自动固定时再扫描。手动固定不自动重扫。

扫描期间可拖动帧滑块、修改候选范围和切换 Process/Measure。已有全量测量计算、原生 SEQ、MP4 或全量 CSV 导出任务期间不启动新扫描；温标扫描期间暂缓启动这些重任务，显示等待或取消扫描的提示。当前帧 PNG 使用冻结快照，允许按第 7.2 节导出。扫描控制器独立管理状态，避免用现有全局 busy 禁用浏览滑块。

请求取消后等待 worker 在帧边界退出。范围、变换或模式连续变化时保留最新待处理请求，前一个 worker 退出后再启动。每个会话最多一个温标扫描 worker。关闭窗口、打开其他文件、进入变换草稿编辑或切换到手动/逐帧模式时取消不再需要的扫描。

因变换编辑或事务切源而中断的自动扫描，在 Cancel 变换、取消文件选择、候选文件准备失败或安装回退后，恢复原会话的调度。仍为自动固定且缺少匹配完成结果时，重新启动对应扫描并更新状态。用户直接点击温标扫描 Cancel 则保持取消状态，等待 Auto range 重试或新的范围/变换触发，页面切换本身不自动重启该任务。

结果返回时再次核验请求输入、源文件状态及任务代次。过期或取消结果不改变界面设置。失败只更新状态并保留可用显示，不能把部分扫描极值发布为完整范围。

当前会话保留一个最近完成的自动结果，匹配全部输入时复用。普通拖帧不重新扫描；切回相同输入的自动固定可复用结果。持久化缓存限于配置中的已完成结果及输入标识，不缓存整段温度图。

## 6. 配置保存与旧版本兼容

selection 格式升级到 v5，继续读取 v1～v4。`display` 保留现有 `colormap`、`vmin_c`、`vmax_c` 字段，并增加温标策略信息。

| 字段 | 语义 |
| --- | --- |
| `scale_mode` | `fixed` 或 `per_frame` |
| `fixed_source` | 固定模式记忆的策略，`auto` 或 `manual` |
| `vmin_c`、`vmax_c` | 保存的固定模式上下限，独立于当前自适应显示范围 |
| `auto_scope` | 最近已完成自动范围的输入标识；未形成匹配的完成结果时为 null |

`auto_scope` 包含源身份摘要、原始帧范围、变换指纹和算法版本。配置加载时严格验证字段、数值及匹配关系。只在完整匹配当前文件、确认范围和变换时把保存的自动值当作已完成结果；其他情况下按当前策略安排新扫描。

`fixed_source=manual` 时保存的 `auto_scope` 为 null，避免把手动数值解释成扫描结果。会话内单独保留的自动缓存可继续用于 Auto range。

扫描完成前允许保存设置，但 `auto_scope` 为 null；记录的固定数值仅供恢复时临时显示，重开后继续计算。尚无固定值的新会话，先以首次有效显示帧的范围初始化固定值记忆，或使用第 3 节的占位规则。随后临时显示的逐帧变化不覆写这份固定值，直到完整自动结果或手动 Apply 生效。切帧时不重复改变配置脏状态。

旧配置 v1～v4 及 `--vmin`、`--vmax` 显式参数均按手动固定恢复，原有数值继续生效。无旧配置、无显式上下限的新会话默认自动固定。旧配置仍可通过 Auto range 主动切换到新的统计规则。

版本迁移继续保存 v4 已有的来源链与高度设置。`provenance` 的读取条件必须覆盖 v4 和 v5，避免升版时丢失已有祖先帧映射。

Process 保存候选范围时，只有候选范围与自动结果范围完全匹配才保存有效 `auto_scope`；其他情况保留自动策略并使范围标识失效。Measure 按已确认范围保存。这样加载任何一份配置时，都能针对实际恢复范围取得对应自动温标。

## 7. 导出的一致性

### 7.1 MP4

导出请求冻结温标模式、固定值、已确认范围和已应用变换。固定自动只有匹配的完整范围就绪后才能进入导出确认。扫描中、失败或取消后的临时范围不能被当作全程固定结果导出，界面提供重试、手动范围或逐帧模式的继续方式。

固定模式的所有视频帧使用同一范围。逐帧模式对实际渲染的每个源帧，在同一变换后的矩阵上计算范围，然后同步更新图像归一化和 colorbar。重复使用同一个源帧的视频采样保持相同上下限。无效帧采用第 3 节的回退并在视频图像中显示无有效温度提示。

确认摘要明确显示固定自动、固定手动或逐帧自适应。自适应视频显示相应模式标识，便于观看者识别颜色随帧重新归一化的行为。保留现有时间戳、播放倍率、尺寸、编码和原子发布流程。

### 7.2 PNG 与 CSV

PNG 使用触发导出时的实际生效上下限和模式标识，冻结快照后独立渲染。自动固定尚未完成时，PNG 可导出当前预览，但须在图中保留临时温标标识。

现有 CSV 温度来自温度矩阵，沿用现有数值定义。与导出一起保存的 selection 或元数据采用新的温标配置字段。温标变化不触发重新计算 ROI 和高度统计。

### 7.3 原生子 SEQ 与配套配置

原生帧提取沿用已有流程。配套 JSON 保存温标模式及固定策略。手动固定值完整保留；自动固定输入标识在子文件身份或输出帧范围改变后失效，重开子文件时按其完整工作范围重新扫描。逐帧模式在重开后继续逐帧计算。当前父文件完成的温标可作为子文件的临时显示值，不能冒充对子文件的匹配扫描结果。

## 8. 验证与验收

实施阶段需要以下可执行检查。

- 新会话默认自动固定，后段高温影响最终上限；逐帧模式只依据当前帧，显示与 colorbar 使用同一对上下限。
- 固定自动包含已确认范围的全部帧；候选范围拖动不扫描，Confirm、Reset full 和应用新变换正确更新范围。
- 裁剪区域外的高温、无效背景、不同 ROI 勾选、模式切换及手动值恢复均符合前述定义。
- NaN/Inf、全无效帧、常温帧、单帧和错误上下限都有明确结果，扫描失败和取消不能发布半成品。
- 快速变更范围、切模式、进入编辑、切换文件和关闭窗口时，过期 worker 无法回写，reader、timer 和线程得到释放。
- 扫描完成不覆盖未 Apply 的输入草稿，切模式可恢复草稿；取消变换或切源失败回退后能正确恢复因内部操作中断的扫描。
- 自动扫描只做有界逐帧处理；拖动帧滑块不触发整段扫描，也不引入已修复的输入框同步整窗绘制。
- v1～v4 配置恢复成原手动固定范围，v5 两种模式可往返，来源链、ROI 与高度标定不丢失。
- 自适应浏览不使设置反复变脏；温标更改不使现有测量结果失效。
- PNG 和 MP4 的固定/逐帧范围与 UI 一致，MP4 固定自动扫描包含视频显示抽帧可能略过的高温帧。
- 原生子 SEQ 的新源身份及候选范围差异使旧自动范围失效，重新打开能建立正确范围。
- 复用最小真实 SEQ 验证两种模式和配置/导出链路，再对 `Q1.seq` 做一次全范围只读扫描，确认结果覆盖第 3259 帧的 50.18053 °C 高温。额外选帧与独立逐帧参考累计核对，不用抽查值代替全局极值验收。
- 真实输入 SEQ 在验证前后核对大小及 mtime。所有导出使用项目内独立临时目录，保留用户已有输出。

本文记录的是设计与待执行验收要求。前述三个抽查帧的读取结果是现有证据，实施、性能和全范围扫描结果将在后续执行记录中单独记录。
