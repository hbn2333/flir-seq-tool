# FLIR SEQ 交互查看与视频导出设计

## 1. 目标

在 `D:\carbonfoam\infrared` 内建立可重复使用的本地工具，用于只读打开 FLIR ResearchIR FFF `.seq` 文件，按帧或时间浏览和截取，并将选定片段导出为可剪辑的 MP4。

工具需要支持在代表帧上定义固定像素坐标的测温点和矩形 ROI。导出期间，这些标注应用到每一帧，显示点温度以及 ROI 的最低、最高温度和对应位置。

第一版不自行解析 FFF 二进制格式。FLIR Science File SDK 2026.1.2 是唯一的 SEQ 解码与工厂标定温度来源。

## 2. 输入与约束

### 2.1 原始输入

- `raw\Rec-000366-240_09_26_37_152.seq`，42,873,727 B。
- `raw\Rec-000367-240_09_26_49_992.seq`，1,518,245,059 B。
- `raw\Rec-000368-240_09_30_50_732.seq`，7,625,825,755 B。
- 三个文件始终只读，不覆盖、不重命名、不写回元数据。

### 2.2 已验证环境

- Windows x64。
- Python 3.13.5 x64。
- FLIR Science File SDK 2026.1.2 Python `cp313` wheel。
- `fnv` 与 `fnv.file` 可导入。
- 最小 SEQ 首帧可直接读为 $640\times480$ 温度矩阵。

### 2.3 辐射测温参数

- 发射率：$\varepsilon=0.95$。
- 反射温度：$T_{refl}=293.15\ \mathrm{K}$。
- 测量距离：$d=1\ \mathrm{m}$。
- 大气温度：$T_{atm}=293.15\ \mathrm{K}$。
- 相对湿度：$RH=0.5$。
- 大气透过率：$\tau_{atm}=1.0$。
- 输出温度单位：$^\circ\mathrm{C}$。

参数必须写入每次导出的配置与清单。不得只依赖进程内默认值。

## 3. 方案选择

采用“官方 FileSDK 解码 + Python 薄封装 + Matplotlib 交互 + FFmpeg/OpenCV 视频编码”的组合。

不采用纯 Python FFF 解析器作为主路径，原因是不同相机和 ResearchIR 版本的 FFF 容器存在兼容性差异，错误结果仍可能呈现为视觉上合理的热图。`flirpy`、`Thermal_Image_Analysis` 和 `SEQfileReader` 只作为接口和交互设计参考，不作为温度真值来源。

## 4. 系统边界

### 4.1 SEQ 读取层

职责：

- 打开和关闭 `fnv.file.ImagerFile`。
- 读取宽度、高度、帧数、帧时间戳和文件级元数据。
- 将 FileSDK 切换为工厂温度与摄氏度输出。
- 显式应用辐射测温参数。
- 按单个帧号返回二维 `float32` 温度矩阵和帧元数据。
- 提供按帧迭代器，任何时刻只保留当前帧和少量缓存帧。

读取层不负责绘图、ROI、视频编码或文件命名。

### 4.2 时间索引层

职责：

- 建立 `frame_index -> timestamp` 索引。
- 将相对时间和绝对时间映射到最近帧。
- 检查时间戳是否递增、是否重复、是否存在异常间隔。
- 用相邻有效时间戳间隔的中位数估计显示帧率：

$$fps=\frac{1}{\operatorname{median}(t_{i+1}-t_i)}$$

- MP4 使用恒定帧率；原始逐帧时间戳完整保存在 CSV 中。

索引只保存帧号和时间，不保存温度矩阵。

### 4.3 交互查看器

Matplotlib 窗口包含：

- 主热图与固定色标。
- 当前帧号、相对时间和绝对时间。
- 底部帧滑块，用于按需读取任意帧。
- 起点和终点选择控件，用于确定导出闭区间 `[start_frame, end_frame]`。
- 添加测温点模式：鼠标单击图像，保存整数像素 `(x, y)`。
- 添加矩形 ROI 模式：鼠标拖拽，保存半开区间 `[x_0,x_1)\times[y_0,y_1)`。
- 删除当前标注和清空全部标注操作。
- 保存选择配置操作。

滑块移动只读取目标帧，不预读整个文件。可使用最多 3 帧的 LRU 缓存改善往返浏览。

### 4.4 标注与统计

测温点使用固定像素坐标。对每一帧读取 `temperature[y, x]`。

矩形 ROI 使用固定像素边界。对每一帧计算：

- 最低温度与其像素坐标。
- 最高温度与其像素坐标。
- 平均温度，作为 CSV 数据保留；第一版画面默认仅叠加最低值和最高值，避免遮挡。

所有坐标在保存前裁剪到图像范围。零宽度或零高度 ROI 被拒绝，并给出明确错误。

### 4.5 固定温标

同一导出片段的所有帧必须使用相同的 `vmin` 和 `vmax`，避免逐帧自动缩放造成虚假温度跳变。

默认值通过对选定片段均匀抽样不超过 100 帧后，计算全部有效像素的第 1 和第 99 百分位确定。用户可以显式覆盖 `vmin` 和 `vmax`。最终采用值写入配置和视频清单。

### 4.6 MP4 导出

导出器逐帧执行：

1. 从 FileSDK 读取一帧摄氏温度矩阵。
2. 使用固定温标映射颜色。
3. 绘制时间、帧号、测温点、ROI、ROI 极值位置和温度色标。
4. 将 RGB 帧立即交给视频编码器。
5. 追加一行测温 CSV。
6. 释放当前大数组引用并进入下一帧。

默认输出 H.264、`yuv420p` MP4，以提高剪辑软件兼容性。若系统 FFmpeg 不可用，工具在导出前失败并报告安装或路径问题，不生成伪成功文件。

第一版输出带温度叠加的 MP4。相同配置可通过 `annotated=false` 再生成无标注的干净 MP4，而不需要重新选择时间和 ROI。

## 5. 输出结构

每次导出使用独立目录：

```text
outputs/
  <seq_stem>/
    <export_id>/
      selection.json
      manifest.json
      temperatures.csv
      annotated.mp4
      clean.mp4              # 仅在请求时生成
      validation.json
```

`selection.json` 保存起止帧、起止时间、点、ROI、色图、温标和辐射测温参数。`manifest.json` 保存输入文件名、文件大小、只读校验信息、SDK/Python 版本、输出编码参数和生成时间。

CSV 至少包含：

- `frame_index`
- `timestamp_absolute`
- `time_relative_s`
- 每个测温点的温度
- 每个 ROI 的 `min/max/mean` 温度
- 每个 ROI 极值的像素坐标
- 帧状态标志

## 6. 异常与质量检查

### 6.1 读取异常

- 单帧读取失败时记录帧号、异常类型和消息。
- 默认停止导出，保留带 `status=failed` 的清单和已写入的临时文件。
- 最终 MP4 先写为 `.partial.mp4`，全部完成并验证后原子重命名为正式文件。

### 6.2 坏帧与 NUC 候选

逐帧或抽样计算：

- 有限像素比例。
- 全帧最小值、最大值、平均值和标准差。
- 相邻帧平均绝对差。
- 时间戳间隔。

明显异常只标记为“候选”，不自动删除。NUC 判断不能只依赖单一阈值；第一版将突变帧与时间戳异常输出到 `validation.json`，由用户复核。

### 6.3 输出验证

- MP4 文件存在且大小大于零。
- 编码器报告的帧数等于 `end_frame-start_frame+1`。
- 视频宽、高和帧率与清单一致。
- CSV 行数等于视频帧数。
- 首帧、末帧和至少一个中间帧的叠加温度与直接温度矩阵重新计算结果一致。
- 原始 SEQ 的文件大小和修改时间在操作前后不变。

## 7. 分阶段实现

### 阶段 A：只读检查器

交付文件信息、帧数、尺寸、首末时间、时间戳连续性摘要，并对最小 SEQ 建立回归测试。

### 阶段 B：单帧查看器

交付帧滑块、固定温标和按需读取。验收标准是能够浏览最小 SEQ，内存不随访问帧数持续增长。

### 阶段 C：时间段与标注

交付起止帧选择、测温点、矩形 ROI 和 `selection.json`。重新载入配置后必须得到相同坐标和统计值。

### 阶段 D：流式 MP4 与 CSV

交付带标注 MP4、可选干净 MP4、逐帧测温 CSV 和导出清单。先对最小 SEQ 全段验收。

### 阶段 E：质量检查与大文件验证

交付坏帧、NUC 候选和时间戳检查。对两个大文件先做首、中、末及稀疏抽样，再做用户指定短片段的完整流式导出；不默认全量导出 7.6 GB 文件。

## 8. 测试策略

- 纯函数单元测试：坐标规范化、时间映射、ROI 统计、温标计算、导出命名和配置往返。
- FileSDK 集成测试：使用最小真实 SEQ 验证尺寸、首帧时间和已知首帧温度范围。
- 编码集成测试：导出短片段并检查帧数、分辨率、CSV 行数和抽样温度。
- 内存测试：长迭代期间记录进程常驻内存，确认没有按帧数线性增长。
- 只读保护测试：导出前后比较三个原始文件的大小和修改时间；必要时增加可选 SHA-256 基线，但不在每次启动时扫描 7.6 GB 文件。

所有新增行为遵循测试先行：先观察测试因缺少行为而失败，再写最小实现使其通过。

## 9. 第一版非目标

- 不修改或重新封装原始 SEQ。
- 不实现相机实时采集。
- 不实现目标跟踪；点和 ROI 不随物体移动。
- 不在第一版提供完整 Qt 桌面应用。
- 不将完整温度视频一次性加载到内存。
- 不将 NUC 候选自动删除或插值。
