# FLIR SEQ 旋转与裁剪设计

## 1. 背景与目标

现有工具已能通过官方 FLIR Science File SDK 2026.1.2 逐帧读取 SEQ 摄氏温度矩阵、筛选时间范围、保存选择配置并原生导出子 SEQ。本阶段在测温点和矩形 ROI 之前增加非破坏式旋转与裁剪，使后续标注统一建立在修整后的稳定坐标系上。

本阶段的目标是：

- 在现有 Matplotlib 查看器中提供步骤少、可预览、可取消、可重新编辑的旋转裁剪工作流。
- 对一份 SEQ 的选中时段固定使用同一套几何变换。
- 明确定义原始、旋转后和裁剪后像素坐标之间的可逆映射。
- 将变换随 selection 配置保存，同时兼容已有 schema v1。
- 保持原始 SEQ 只读；旋转裁剪只影响显示、后续分析和未来派生输出。
- 继续按需逐帧读取和处理，不把大文件整体载入内存。

唯一有效工作目录为 `D:\carbonfoam\infrared`。已经失效的 `D:\carbonfoam\红外` 不得使用。原始 SEQ 固定存放在 `D:\carbonfoam\infrared\raw`，不得覆盖、修改或重命名。

## 2. 已选方案与备选方案

### 2.1 采用方案：单窗口变换模式

主查看器增加 `Edit transform`。点击后仍使用同一窗口，但控制区从普通浏览工具切换为旋转裁剪工具。图像区显示完整旋转预览、无效区和裁剪框；`Apply` 或 `Cancel` 后返回普通浏览模式。

该方案的优点是没有弹窗焦点和同步问题，画面区域不会被两套控件同时挤占，并且重新编辑只需再次点击一个按钮。它最符合商用图像软件常见的非破坏式编辑方式。

### 2.2 未采用方案：独立编辑窗口

独立窗口能提供充足编辑空间，对主界面侵入较小，但会增加 Windows 下的窗口焦点、关闭事件、主从状态同步和异常恢复复杂度。

### 2.3 未采用方案：旋转—裁剪向导

分步向导容易理解，但用户在旋转和裁剪之间反复调整时点击次数多，不符合本阶段追求的快速预览与重新编辑体验。

## 3. 用户工作流

### 3.1 普通浏览模式

普通模式维持现有逐帧浏览、时间范围选择、selection 保存/加载和原生子 SEQ 导出能力，并新增 `Edit transform`。图像只显示已经应用的裁剪结果，不显示旋转画布的灰色无效区。

状态栏显示当前变换，例如：

```text
Transform: applied | angle -2.3° | crop 18,12,592×438
```

若变换已经应用到会话但尚未保存到 selection 文件，则显示 `Transform: applied, unsaved`。

### 3.2 进入编辑模式

进入编辑模式时，以当前已应用变换复制出一份独立草稿。首次编辑的起点是 `0° + 完整原图`。编辑期间：

- 保留当前帧滑块，允许切换不同帧检查同一套变换。
- 时间范围确认、selection 保存/加载和子 SEQ 导出控件隐藏或禁用。
- 图像区显示旋转后的完整扩展画布。
- 旋转产生的无效区域显示为灰色棋盘或纯灰遮罩。
- 裁剪框及其四边、四角控制点叠加在预览图上。

### 3.3 旋转控件

第一版不做自动找水平，采用手动旋转：

- `左转90°`、`右转90°`、`180°` 和 `归零` 快捷按钮。
- 围绕当前整 90° 方向的微调滑块，范围为 `-15.0°` 至 `+15.0°`，步长为 `0.1°`。
- 总角度输入框显示快捷旋转与微调合成后的角度。
- 总角度输入仅接受整 90° 方向上下 `15.0°` 范围内、精度为 `0.1°` 的值。
- 用户可见的正角度表示逆时针旋转。
- 保存时只记录标准化到 `[-180°, 180°)` 的合成总角度，例如 `87.7°`，不分别保存快捷方向和微调值。

任何角度变化都会重新计算旋转画布和有效区域，并把裁剪框重置为新角度下的最大有效内接矩形。界面提示 `Rotation changed — crop reset`。该规则避免静默保留已经失效或包含空白的旧裁剪框。

### 3.4 裁剪控件

用户可以：

- 在图像上创建和移动矩形裁剪框。
- 拖动四边或四角控制点缩放裁剪框。
- 使用 `x`、`y`、`width`、`height` 整数输入框做单像素微调。
- 点击 `Maximum valid area` 一键恢复当前角度下的最大有效内接矩形。

鼠标与数字输入保持双向同步。合法裁剪框正常显示；越界、尺寸非正或包含旋转空白时显示为红色，并禁用 `Apply`。

### 3.5 草稿操作

- `Apply`：重新校验草稿并要求当前帧预览变换成功，然后提交为会话中的已应用变换并返回普通模式。它不立即写磁盘。
- `Cancel`：丢弃草稿，恢复进入编辑模式前的已应用变换。
- `Reset draft`：把当前草稿重置为 `0° + 完整原图`，但仍停留在编辑模式，不改变已应用变换。
- `Edit transform`：再次进入时以当前已应用变换为起点继续编辑。

执行顺序固定为先旋转、后裁剪。

## 4. 几何模型与温度重采样

### 4.1 像素与旋转中心

原始图像尺寸为 `W × H`。像素中心使用整数坐标，原图几何中心固定为：

```text
((W - 1) / 2, (H - 1) / 2)
```

第一版不允许用户改变旋转中心。对于水平校正，自定义中心不会改变旋转方向，只会改变内容在画布中的平移位置，因此不值得增加额外交互和配置复杂度。

### 4.2 扩展画布

旋转采用扩展画布，保证原始内容不会在旋转步骤中先被裁掉。旋转画布尺寸由原图尺寸、像素中心约定和标准化角度确定性推导。`0°` 时画布尺寸必须精确等于原图尺寸。

### 4.3 双线性重采样

任意角度旋转后，新规则像素网格通常不会与原始测温像素中心重合，因此必须重采样。温度矩阵采用双线性插值。插值结果是可追溯的派生温度，不被表述为相机新增的直接测量值。

有效像素掩码独立于温度值计算，不能根据温度大小判断有效性。每个输出像素中心通过反向映射落在原始图像有效坐标范围内时才有效。裁剪框内所有像素都必须有效，因此正式裁剪结果不包含由旋转空白产生的 `NaN`。若原始温度矩阵自身含有非有限值，应单独报告并按源数据质量问题处理，不能用几何裁剪掩盖。

`0° + 完整原图` 使用恒等快速路径，不调用插值器，不改变尺寸或温度值。

### 4.4 裁剪语义

裁剪框使用旋转画布的整数坐标：

```text
x, y, width, height
```

它覆盖 `x ... x + width - 1` 和 `y ... y + height - 1` 的像素。`width` 和 `height` 必须为正整数。

最大有效区域通过布尔有效掩码上的最大全真轴对齐矩形算法求得。若多个矩形面积相同，固定选择更靠上者；仍并列时选择更靠左者，以保证测试和保存结果可重复。`0°` 时结果必须是完整原图。

## 5. 坐标系与映射契约

定义三个坐标系，均以左上角为原点、`x` 向右、`y` 向下，并以像素中心为坐标位置：

```text
原始坐标 S
   │  绕几何中心旋转，并平移到扩展画布
   ▼
旋转画布坐标 R
   │  减去裁剪框左上角 (crop_x, crop_y)
   ▼
裁剪后坐标 C
```

内部使用确定的 `3×3` 齐次仿射矩阵：

```text
R = M_source_to_rotated · S
C = R - (crop_x, crop_y)

R = C + (crop_x, crop_y)
S = M_rotated_to_source · R
```

变换模块提供以下公开接口：

- `source_to_rotated`
- `rotated_to_source`
- `source_to_cropped`
- `cropped_to_source`

矩阵从源尺寸、角度和扩展画布规则重新计算，不在 JSON 中重复保存。

后续测温点和矩形 ROI 以裁剪后坐标系作为唯一权威坐标：

- 测温点保存裁剪后像素坐标，其每帧温度是修整后温度矩阵对应位置的双线性重采样值。
- 矩形 ROI 保存裁剪后的整数 `x`、`y`、`width` 和 `height`，统计直接在修整后温度矩阵上执行。
- 后续标注记录声明 `coordinate_space: "cropped_pixel_v1"` 并关联当前变换的稳定指纹。
- 裁剪后点映射回原图时通常是浮点位置；裁剪后轴对齐矩形映射回原图时通常是旋转四边形。
- 原图位置或四边形仅在报告、审计和导出时计算，不作为第二套权威坐标保存。

如果未来已经存在测温点或 ROI，再次修改并应用变换时必须明确警告并要求清除旧标注。第一版不自动迁移点或矩形 ROI，避免矩形迁移后不再轴对齐以及两类标注行为不一致。

## 6. selection schema v2

### 6.1 JSON 结构

现有 `schema_version: 1` 升级为 v2，并在根对象增加严格校验的 `transform`：

```json
{
  "schema_version": 2,
  "source": {
    "filename": "example.seq",
    "size_bytes": 123456,
    "modified_time_ns": 1788253200000000000,
    "width": 640,
    "height": 480,
    "num_frames": 1000,
    "first_timestamp": "2026-09-01T12:00:00",
    "last_timestamp": "2026-09-01T12:00:39.960000"
  },
  "selection": {
    "source_start_frame": 100,
    "source_end_frame": 500,
    "start_timestamp": "2026-09-01T12:00:04",
    "end_timestamp": "2026-09-01T12:00:20",
    "frame_count": 401,
    "duration_s": 16.0
  },
  "display": {
    "colormap": "inferno",
    "vmin_c": 20.0,
    "vmax_c": 120.0
  },
  "transform": {
    "rotation": {
      "angle_deg": -2.3,
      "center": "source_image_center",
      "canvas": "expand",
      "interpolation": "bilinear"
    },
    "crop": {
      "x": 18,
      "y": 12,
      "width": 592,
      "height": 438
    }
  }
}
```

### 6.2 严格校验

v2 继续拒绝缺失字段、未知字段、非法类型和非有限数值。额外规则为：

- `angle_deg` 位于 `[-180, 180)`。
- 角度符合 `0.1°` 精度，并处于某个整 90° 方向上下 `15.0°` 的允许范围内；等价地，角度到最近的 `90°` 整数倍的环形距离不超过 `15.0°`，因此 `-180.0°` 合法而 `180.0°` 必须先标准化为 `-180.0°`。
- `center` 固定为 `source_image_center`。
- `canvas` 固定为 `expand`。
- `interpolation` 固定为 `bilinear`。
- 加载时重新计算旋转画布和有效掩码，再验证裁剪框尺寸为正、没有越界且所有像素有效。

旋转矩阵、旋转画布尺寸、输出尺寸等可推导信息不写入 JSON，避免冗余字段不一致。

### 6.3 v1 兼容

v1 文件加载为内存中的恒等变换：

```text
angle = 0°
crop = (0, 0, source_width, source_height)
```

读取 v1 不修改磁盘。只有用户主动点击 `Save selection` 时才以 v2 写回。保存继续使用现有临时文件校验、原子替换和单份 `.bak`；源文件身份仍严格核验文件名、大小、`mtime_ns`、宽高、帧数和首末时间。

### 6.4 应用、保存与加载

- `Apply` 只更新当前会话并标记未保存。
- `Save selection` 将时间范围、固定温标和变换保存为同一份一致快照。
- `Load selection` 一次恢复时间范围、固定温标和变换。
- 若当前会话存在未保存修改，第一次点击 `Load selection` 只显示覆盖摘要，第二次点击才确认加载。
- 配置损坏、非法或源身份不匹配时整体拒绝加载，不局部套用。

## 7. 原生子 SEQ 与数据安全边界

旋转裁剪只改变显示、后续测温分析和未来派生图像或视频输出，不修改原始 SEQ，也不把变换烘焙进原生子 SEQ。

现有子 SEQ 导出继续按源帧闭区间调用 FileSDK，传递原始辐射帧。导出请求不包含 transform，导出语义与当前版本一致。

任何自动测试和真实文件验证都不得写入 `raw`。selection 集成测试使用 pytest 临时目录，不写生产 `selections`。

## 8. 模块边界

### 8.1 `transform.py`

- 定义不可变的 `RotationSettings`、`CropRect` 和 `FrameTransform`。
- 负责参数验证、扩展画布尺寸、正逆矩阵和坐标映射。
- 负责有效掩码和最大有效矩形算法。
- 不依赖查看器控件或 FileSDK。

### 8.2 `frame_transformer.py`

- 预计算当前变换的反向采样坐标。
- 使用双线性插值处理单帧温度矩阵。
- 提供恒等快速路径。
- 普通浏览模式只为最终裁剪尺寸建立采样坐标；编辑模式才生成完整旋转预览。

### 8.3 `transform_editor.py`

- 管理独立草稿状态。
- 管理旋转控件、裁剪框拖拽、控制点和数字输入同步。
- 管理合法性视觉反馈以及 `Apply`、`Cancel`、`Reset draft`。
- 不直接读写 selection 文件。

### 8.4 `selection.py`

- 增加 transform JSON 序列化、反序列化和严格校验。
- 按 schema 版本分派解析，并把 v1 在内存中迁移为恒等变换。
- 保持现有原子保存、备份和源身份核验边界。

### 8.5 `viewer.py`

- 协调普通浏览模式和变换编辑模式。
- 管理已应用变换、草稿、脏状态和加载确认。
- 不承载底层旋转数学。

## 9. 性能与缓存

- FileSDK 继续按需读取单帧摄氏温度矩阵。
- 一份 SEQ 的选中时段固定使用同一套已应用变换。
- 几何矩阵、有效掩码和反向采样坐标只在变换变化时重算。
- 原始帧缓存与修整后帧缓存分离。
- 修整后帧缓存键包含源帧号和变换指纹。
- `Apply`、`Load selection` 或变换重置后使修整后缓存失效，不影响 FileSDK 源帧缓存。
- 浏览时只生成当前请求帧，不预处理整段 SEQ。

双线性采样使用当前环境已验证的 `scipy.ndimage`，设置一阶插值并禁用不需要的高阶预滤波。项目运行依赖应正式声明 NumPy、Matplotlib 和 SciPy，避免依赖机器上的隐式安装状态。

## 10. 错误处理与状态一致性

- 非数字、超范围或精度非法的角度输入不改变上一个合法草稿；控件恢复并显示错误。
- 鼠标可暂时形成非法红色裁剪框，但此时 `Apply` 禁用。
- 非法数字裁剪输入不覆盖上一个合法数值状态。
- 帧变换失败时保留上一张成功显示的图和已应用配置，不显示半更新状态。
- `Apply` 前重新完整校验，并要求当前帧预览成功；失败时草稿不提交。
- selection 加载采用整体校验和整体应用，不允许时间范围成功但变换失败等部分状态。
- 关闭或退出编辑模式只能通过明确的 `Apply` 或 `Cancel` 结束草稿；窗口关闭沿用查看器既有安全关闭流程。

## 11. 测试设计

### 11.1 几何与数值单元测试

- `0°` 恒等变换保持尺寸、坐标和温度值完全不变。
- `90°`、`180°`、`-90°` 验证方向、画布尺寸和已知小矩阵结果。
- 任意合法角度验证正向—反向坐标往返误差。
- 验证奇数和偶数宽高下的几何中心。
- 用已知温度梯度矩阵验证双线性插值值。
- 验证有效掩码、裁剪边界和裁剪后无 `NaN`。
- 验证最大有效矩形面积及并列选择规则。
- 验证角度变化使裁剪重置。
- 验证恒等快速路径不调用插值器。

### 11.2 配置与状态单元测试

- v2 transform JSON 严格往返。
- v1 加载为恒等变换且磁盘不自动改写。
- 未知字段、非法类型、非有限值、非法角度和非法裁剪均被拒绝。
- `Apply`、`Cancel`、`Reset draft` 和重新编辑的状态转换。
- 非法草稿不能覆盖已应用配置。
- 未保存标记、加载二次确认和保存后标记清除。
- 修整帧缓存按帧号和变换指纹隔离并正确失效。

### 11.3 查看器无头测试

- 普通模式与编辑模式的控件显隐和启用状态。
- 当前帧切换保持同一变换草稿。
- 角度滑块、输入框和快捷按钮双向同步到 `0.1°`。
- 裁剪框与数字输入同步。
- 非法裁剪显示红色并禁用 `Apply`。
- 应用后图像尺寸、坐标轴和状态栏更新。
- 原生子 SEQ 导出请求不包含变换，现有导出语义不变。

### 11.4 按需读取测试

使用可追踪的假 reader 验证：

- 启动查看器不读取整段 SEQ。
- 建立和应用变换不预读所有帧。
- 切换到哪一帧才读取和处理哪一帧。
- 小容量缓存不会随总帧数线性增长。

### 11.5 最小真实 SEQ 只读集成验证

- 从 `D:\carbonfoam\infrared\raw` 只读选择体积最小的 SEQ。
- 测试前记录大小和 `mtime_ns`。
- 读取首帧、中间帧和末帧。
- 应用一个非零合法角度和最大有效裁剪。
- 验证三个输出尺寸一致、温度有限且可以逐帧浏览。
- selection 保存和重新加载使用 pytest 临时目录。
- 测试后再次核对原始文件大小和 `mtime_ns` 完全不变。

另外两份较大 SEQ 不纳入自动旋转裁剪验证，由用户手动验证。全部现有测试和新增测试必须通过；当前基线为 `118 passed`。

## 12. 范围边界

第一版不包含：

- 自动找水平。
- 自定义旋转中心。
- 每帧独立变换、关键帧插值或运动配准。
- 透视校正、翻转、缩放或非矩形裁剪。
- 测温点和 ROI 的实际创建与统计。
- 把变换烘焙进原生子 SEQ。
- GPU 加速、整段预处理或变换历史栈。
- 另外两份大 SEQ 的自动旋转裁剪验证。

## 13. 验收标准

用户能够完成以下最短工作流：

```text
打开 SEQ
→ 选择当前帧
→ Edit transform
→ 快捷旋转（如需要）
→ 滑块微调至 0.1°
→ 拖出裁剪框或选择最大有效区域
→ 数字输入单像素修正
→ 切换首/中/末帧检查同一变换
→ Apply
→ 普通模式逐帧浏览修整结果
→ Save selection
→ 关闭并重新打开
→ Load selection 后得到相同角度、裁剪尺寸和温度结果
```

功能验收条件为：

- 原始 SEQ 的大小和 `mtime_ns` 不变。
- 恒等变换与原始温度矩阵完全一致。
- 对有限的原始温度矩阵，任意合法角度下的正式裁剪输出没有旋转空白和非有限温度。
- 同一变换对所有帧产生相同输出尺寸。
- 保存—加载后配置、坐标映射和数值结果可重复。
- 大文件继续按需逐帧读取，不因变换功能整体载入内存。
- 原生子 SEQ 导出行为与现有版本一致。
- 全部既有测试和新增测试通过。
