# FLIR SEQ 阶段 C2 选择配置与原生子序列导出设计

## 1. 目标

在现有只读 SEQ 时间范围查看器上增加两个连续交付：

- C2a：将当前候选范围与固定温标保存为可重新载入的选择配置。
- C2b：使用官方 FLIR Science File SDK 将当前候选范围原生提取为新的 SEQ 文件。

该阶段解决“先筛选有效时段，再保存可复用子序列”的问题。旋转裁剪、测温点、矩形 ROI、逐帧统计和 MP4 导出不属于本阶段。

## 2. 数据与安全边界

- 唯一有效工作目录为 `D:\carbonfoam\infrared`。
- 原始 SEQ 位于 `D:\carbonfoam\infrared\raw`，始终只读。
- 不覆盖、不改写、不重命名原始 SEQ，不写回其元数据。
- 选择配置固定保存到 `D:\carbonfoam\infrared\selections`。
- 子序列固定保存到 `D:\carbonfoam\infrared\clips`。
- SEQ 解码与子序列提取只使用已安装的 FLIR Science File SDK 2026.1.2。
- 导出直接传递原始帧闭区间，不把完整温度序列载入内存。

## 3. 交付拆分与组件边界

### 3.1 C2a：选择配置

新增独立配置模块，负责：

- 构造源文件身份信息。
- 将候选局部范围转换为原始帧范围。
- 校验 JSON 结构、版本和字段类型。
- 原子保存、单份备份和严格载入。

配置模块不依赖 Matplotlib。查看器只负责读取当前界面状态、调用配置模块，并在成功载入后更新界面。

### 3.2 C2b：原生子序列提取

新增独立提取模块，负责：

- 验证导出请求与目标路径。
- 配置 `fnv.file.ImagerFileExtractOptions`。
- 调用 `ImagerFile.extract()`。
- 上报进度、响应取消并返回明确结果。
- 验证临时输出，成功后原子替换正式目标。

查看器负责两次点击确认、后台线程生命周期、控件锁定、进度显示和窗口关闭协调。后台线程不得直接修改 Matplotlib 控件。

## 4. 帧范围语义

保存和导出的对象都是 `Selected range` 当前候选范围，不要求用户先点击 `Confirm range`。

设当前工作区间原始起点为 `source_start`，候选局部闭区间为 `[pending_start, pending_end]`，则：

$$export\_start = source\_start + pending\_start$$

$$export\_end = source\_start + pending\_end$$

帧数为：

$$frame\_count = export\_end - export\_start + 1$$

FileSDK 的 `start_frame` 和 `end_frame` 均按闭区间传入，`decimation=1`。单帧选择合法。

## 5. C2a 选择配置

### 5.1 路径与命名

每个源 SEQ 只有一份当前配置：

```text
selections/
  <seq_stem>.selection.json
  <seq_stem>.selection.json.bak
```

界面提供显式的 `Save selection` 和 `Load selection` 按钮，不自动保存，也不在启动时自动载入。

### 5.2 JSON 模式

第一版模式版本为 `1`：

```json
{
  "schema_version": 1,
  "source": {
    "filename": "example.seq",
    "size_bytes": 123456,
    "modified_time_ns": 1234567890,
    "width": 640,
    "height": 480,
    "num_frames": 65,
    "first_timestamp": "2026-08-28T09:26:37.152000",
    "last_timestamp": "2026-08-28T09:26:38.932000"
  },
  "selection": {
    "source_start_frame": 16,
    "source_end_frame": 64,
    "start_timestamp": "2026-08-28T09:26:37.592000",
    "end_timestamp": "2026-08-28T09:26:38.932000",
    "frame_count": 49,
    "duration_s": 1.34
  },
  "display": {
    "colormap": "inferno",
    "vmin_c": 22.5,
    "vmax_c": 34.5
  }
}
```

时间戳使用 ISO 8601 字符串，保留 FileSDK 可提供的微秒精度。`duration_s` 定义为末帧时间戳减首帧时间戳；单帧范围为 `0.0`。

### 5.3 源文件严格匹配

载入前必须逐项匹配：

- `schema_version`。
- 文件名。
- 文件大小。
- 纳秒级修改时间 `mtime_ns`。
- 总帧数。
- 宽度和高度。
- 首帧时间戳和末帧时间戳。

任一项不一致即拒绝载入。错误信息指出不匹配字段；时间轴、当前帧、固定温标和画面保持原状。

### 5.4 保存事务

保存顺序为：

1. 从当前候选范围构造完整配置。
2. 写入同目录临时文件。
3. 重新读取临时文件并执行模式与值校验。
4. 若正式配置已存在，用正式配置原子替换唯一的 `.bak`。
5. 用已验证临时文件原子替换正式配置。
6. 若第 5 步失败且正式配置缺失，立即用 `.bak` 恢复正式配置；若恢复也失败，错误信息必须同时报告正式路径与可恢复的备份路径。

保存按钮不增加二次确认。失败时删除本次临时文件。保存事务必须满足：旧正式配置仍存在，或其完整副本可从固定 `.bak` 路径恢复；界面报告失败阶段和恢复状态。

### 5.5 载入行为

成功载入后：

- 配置中的原始帧闭区间成为新的已确认工作区间。
- 局部帧重新编号为 `0` 至 `frame_count-1`。
- 当前帧设为局部第 `0` 帧。
- 候选范围设为新工作区间全长。
- 恢复配置中的 `colormap`、`vmin_c` 和 `vmax_c`。
- 刷新滑块、输入框、标题、状态文本和热图。

载入的所有验证必须在界面状态变更前完成，避免半载入状态。

## 6. C2b 子 SEQ 导出

### 6.1 界面

在现有范围控件附近增加：

- `Clip name` 文本输入框。
- `Export sub-SEQ` 按钮。
- 导出摘要与错误文本。
- 进度指示。
- `Cancel export` 按钮。

用户只输入文件主名。程序固定写入 `clips` 并自动补充 `.seq`。名称必须去除首尾空白，且拒绝：

- 空名称。
- `/` 或 `\` 路径分隔符。
- Windows 非法字符 `< > : " | ? *`。
- `.`、`..`。
- Windows 保留设备名，包括带扩展形式的 `CON`、`PRN`、`AUX`、`NUL`、`COM1` 至 `COM9`、`LPT1` 至 `LPT9`。
- 末尾为空格或句点的名称。

### 6.2 两次点击确认

第一次点击 `Export sub-SEQ` 只执行预检并显示：

- 完整目标路径。
- 原始起止帧。
- 起止时间戳。
- 帧数。
- 持续时间，单位为秒。
- 目标是否已存在以及是否会被覆盖。

预检通过后按钮文本改为 `Confirm export`。第二次点击才开始提取。

在第二次点击前，只要候选范围、当前工作区间或 `Clip name` 发生变化，未执行的确认立即失效，按钮恢复为 `Export sub-SEQ`，要求重新预检。已存在目标允许覆盖，但不得静默覆盖。

### 6.3 预检

开始后台任务前检查：

- 候选范围可转换为合法原始闭区间。
- `clips` 目录可创建且可写。
- 正式目标不是原始输入文件，也不位于 `raw`。
- 临时目标和正式目标不是同一路径。
- 磁盘可用空间满足保守估计。

空间估计使用源文件平均每帧字节数：

$$estimated\_bytes = \left\lceil\frac{source\_size}{source\_frames}\times export\_frames\right\rceil$$

预检要求可用空间至少覆盖 `estimated_bytes` 加固定安全余量；安全余量设为估计值的 $10\%$ 与 $64\ \mathrm{MiB}$ 中的较大者。该检查是早期拒绝机制，不承诺输出文件一定等于估计大小。

### 6.4 FileSDK 提取参数

正式提取使用：

- `start_frame = export_start`。
- `end_frame = export_end`。
- `decimation = 1`。
- `preset = -1`（等价于 `fnv.Preset.ANY`），按 SDK 约定提取全部预设。
- `preferredFormat = "SEQ-FFF"`；开始提取前确认 `ImagerFileWriter.get_writable_formats()` 包含该字符串，找不到时预检失败，不回退到其他容器。
- `progress_callback` 用于进度和取消请求。

输出先写入与正式目标同目录、名称唯一的 `.partial.seq`。提取器不通过逐帧 Python 温度矩阵重建 SEQ。

### 6.5 后台执行与取消

FileSDK 提取在单个后台线程中运行。主线程通过 Matplotlib 定时器轮询线程安全状态对象，更新进度和结果。

后台线程按源路径创建并关闭自己的 `ImagerFile`，不复用查看器主线程持有的读取对象。输出验证也在后台线程内使用独立只读句柄，避免跨线程共享 FileSDK 状态。

导出期间：

- 锁定范围滑块、帧输入框、确认/重置范围、配置保存/载入、名称输入和导出按钮。
- 查看器不启动第二个导出任务。
- `Cancel export` 保持可用。
- 进度回调只更新线程安全状态，不直接操作界面。

取消时，进度回调在观察到取消事件后返回 `True`；需要主动中断时调用同一提取选项对象的 `abort()` 方法。后台线程退出后删除本次 `.partial.seq`，正式目标保持不变。

关闭窗口时若任务仍在运行，先请求取消，禁止把尚在使用的 FileSDK 对象当作已完成资源销毁；工作线程负责退出和清理临时文件。

### 6.6 输出验证与提交

提取返回成功后，重新用 FileSDK 只读打开临时 SEQ，验证：

- 文件可打开。
- 宽度和高度等于源文件。
- 总帧数等于 `frame_count`。
- 临时文件首帧时间戳等于源文件 `export_start` 时间戳。
- 临时文件末帧时间戳等于源文件 `export_end` 时间戳。
- 临时文件首帧摄氏温度矩阵与源文件所选首帧相等；浮点比较使用测试中定义的严格容差。
- 原始源文件大小和 `mtime_ns` 与任务开始前一致。

全部通过后才将临时文件原子替换为正式目标。若正式目标已存在，替换发生在验证之后；不为导出 SEQ 自动创建备份。任何失败都保留既有正式目标，并清理本次临时文件。

## 7. 错误状态与恢复

界面将导出状态明确区分为：

- 未预检。
- 等待二次确认。
- 正在导出。
- 已取消。
- 失败。
- 成功。

错误消息至少包含失败阶段和直接原因，例如名称非法、空间不足、FileSDK 异常、取消、输出验证失败或原始文件身份变化。线程异常必须被捕获并传回主线程，不得只输出到终端。

所有失败路径遵循以下不变量：

- 原始 SEQ 未改变。
- 既有正式目标未改变。
- 本次临时文件被清理。
- 控件最终恢复可操作状态。
- 时间轴与当前画面保持有效状态。

## 8. 测试策略

### 8.1 C2a 单元测试

- 候选局部范围正确映射为原始帧范围。
- JSON 保存与载入往返保持全部字段。
- 未知模式版本被拒绝。
- 缺失字段、错误类型、反向范围、错误帧数和错误持续时间被拒绝。
- 八项源身份检查逐项生效。
- 已有配置被保存时只保留一份 `.bak`。
- 临时写入或验证失败时，既有正式配置可恢复。
- 载入失败不改变时间轴、色图、温标或当前画面。
- 载入成功后范围成为已确认工作区间并重新编号。

### 8.2 C2b 单元测试

- 自定义名称校验覆盖合法名称、非法字符、路径分隔符、保留名和末尾句点/空格。
- 目标扩展名和固定输出目录正确。
- 候选局部范围映射正确，FileSDK 端点为闭区间。
- 第一次点击只生成摘要，第二次点击才创建任务。
- 名称或范围变化使未执行确认失效。
- 已有目标被标记为覆盖，且第一击不会修改它。
- 进度状态可从工作线程安全传递到主线程。
- 导出期间相关控件锁定，结束后恢复。
- 取消、SDK 异常、线程异常和验证失败均清理临时文件并保留正式目标。
- 使用伪 FileSDK 对象验证参数、进度、取消与失败分支。

### 8.3 真实 SEQ 集成测试

使用最小文件 `raw\Rec-000366-240_09_26_37_152.seq` 提取一个短范围：

- 输出帧数等于闭区间长度。
- 输出尺寸为 $640\times480$。
- 输出首末时间戳对应源范围端点。
- 输出首帧温度矩阵与源所选首帧一致。
- 测试前后原始文件大小和 `mtime_ns` 不变。
- 集成测试输出使用隔离临时目录，不覆盖用户 `clips` 中的文件。

## 9. 实施顺序与检查点

1. 实现 C2a 的纯配置模型、原子文件操作与单元测试。
2. 将保存/载入按钮接入查看器，完成 C2a 界面与真实 SEQ 回归测试。
3. 实现 C2b 的请求模型、名称/空间预检、FileSDK 提取封装和伪 SDK 单元测试。
4. 接入两次点击确认、后台线程、进度、取消和控件锁定。
5. 使用最小真实 SEQ 完成短片段提取、验证与原始文件只读检查。

C2a 和 C2b 分开提交和验证，便于定位问题与回退。

## 10. 完成判据

- 用户可显式保存当前候选范围，并在同一源文件上严格校验后重新载入。
- 载入后得到相同原始帧范围、局部编号和固定温标。
- 用户可自定义子 SEQ 名称，并在第二次点击确认后导出当前候选范围。
- 已有目标允许覆盖，但覆盖只发生在新文件完整提取并验证之后。
- 导出期间界面保持响应，显示进度并可取消。
- 成功输出可被 FileSDK 重新打开，帧数、尺寸、端点时间戳和首帧温度均通过验证。
- 所有失败路径不破坏既有目标，且不遗留本次临时文件。
- 原始 SEQ 的大小和纳秒级修改时间保持不变。

## 11. 后续范围

C2 完成后再进入以下阶段：

1. 在任何点或矩形标注之前增加旋转与裁剪，并定义源像素到显示像素的坐标变换。
2. 在变换后的画面上添加固定测温点。
3. 添加矩形 ROI 及最低、最高和平均温度读取。
4. 流式导出固定温标 MP4、标注数据和温度矩阵。
