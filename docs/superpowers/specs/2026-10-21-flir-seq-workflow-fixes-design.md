# FLIR SEQ 初版工作流修复设计

日期：2026-10-21。基线：`v0.1.0`，提交 `2b1a5d7`。

状态：交互规则已在对话中确认；本文待用户书面审核。本文不是实现完成报告。

## 1. 范围与不可变约束

本轮完成 `BUG-004`、`UX-001`、`EXP-001`：编辑模式布局、配置选择与另存、原生子 SEQ 配套 selection 导出及自动恢复。

- 唯一工作目录：`D:\carbonfoam\infrared`。原始 `raw` 文件始终只读，不改名、不覆盖、不写回元数据。
- 保留 Matplotlib 单窗口查看器和官方 FileSDK，不迁移到网页或新的桌面框架。
- 保留逐帧读取与有界缓存；不得整段载入温度矩阵。
- 不新增测温点、ROI、曲线、实验零点、MP4 或重采样 SEQ 写入功能。
- 保留旋转角度、插值、坐标映射与当前温度计算规则。
- 保留 `v0.1.0` 标签；在修复分支分项提交，不移动既有标签、不强制推送。发布版本号与标签在验收后确认。

## 2. 已确认的方案与取舍

配置管理比较了“每次保存都弹框，保留两个按钮”与“Save、Save As、Load 三个按钮”。用户选择前者：减少按钮，不引入隐式的当前文件快速覆盖操作。

配套配置比较了“启动时自动核验恢复”与“手动 Load”。用户选择自动恢复，并要求核验失败时保持原始视图且明确提示。

导出选择原生 SEQ 加同名 selection，而不是重写旋转裁剪后的温度像素。这样保留原始测量矩阵与可编辑变换；代价是其他软件单独读取 SEQ 时仍显示原始方向与尺寸。

## 3. BUG-004：布局和模式切换

### 3.1 原因

`viewer.py` 用 figure 文本显示状态，但模式切换只隐藏普通控件 axes。`transform_editor.py` 又在相同底部区域放置按钮和输入框，导致状态文字与按钮重叠。滑块右侧数值和文本框标签也没有预留独立空间。

### 3.2 设计

- 图像及色条、当前帧滑块、模式专属控件、状态/错误信息使用互不重叠的区域。
- 普通模式显示范围、配置、导出控件；编辑模式隐藏普通模式专属控件、旧导出摘要及进度信息，显示旋转裁剪控件。
- 当前帧及时间信息继续可见，但放在独立信息区域；明确区分已应用变换和编辑草稿，避免将旧的 applied 状态误认为当前预览。
- 角度输入标签和滑块数值各有空间。裁剪标签放在输入框上方或各自预留的标签区域，不侵占相邻输入框。
- Maximum、Reset、Cancel、Apply 排为独立操作行，不与状态文字混排。
- 文本换行应按可用宽度处理。较长的配置/输出路径允许缩略展示，但成功、失败、覆盖确认信息必须能获取完整路径；不得因为排版隐藏关键警告。
- 共享布局参数负责区域划分，避免两个模块分别硬编码同一区域。只抽取与本轮布局有关的代码，不重构整个查看器。

### 3.3 尺寸和验证边界

至少验证画布逻辑尺寸 1000×800、1200×1000、1600×1000，以及 100/150/200 DPI 的组合。逻辑尺寸以 100 DPI 为基准，测试升高 DPI 时保持画布英寸尺寸不变、物理像素数同比增加，避免混淆高 DPI 与缩小窗口。按实际 renderer 的文字包围盒检查控件与非关联文字不重叠，并检查可见内容没有越出画布。

小于最低支持尺寸时给出放大窗口提示，不宣称任意尺寸均可用。Windows 屏幕缩放仍需真实窗口人工验收，不能只用 Agg 截图代替。

## 4. UX-001：配置保存与加载

### 4.1 Save selection

- 保留按钮名称，每次点击均打开原生保存文件对话框。
- 初始目录为 `selections`，建议文件名为 `<源SEQ文件名去扩展名>.selection.json`。用户可更改名称及目录。
- 文件类型限定 selection JSON；缺少后缀时补齐 `.selection.json`，其他不符合约定的后缀应提示，不将 JSON 写成 `.seq`。
- 保存当前候选范围、固定温标/色图及已应用变换，与既有含义一致；编辑草稿不能直接保存，须先 Apply 或 Cancel。
- 已有目标须确认覆盖。取消文件选择或覆盖确认，不写文件、不改变脏标记或当前配置路径。
- 成功后显示实际保存路径并更新干净状态。失败保留现有查看状态，不报告保存成功。
- 保留临时文件校验、原子替换和单份 `.bak`。覆盖确认后到替换前核对目标快照，目标被外部创建或修改时拒绝覆盖，要求重新确认。

### 4.2 Load selection

- 每次点击打开原生打开文件对话框，初始目录为 `selections`，也可选择 `clips` 中配套文件。
- 取消不改变当前状态。选定文件后读取、严格核验源身份、schema、范围、变换和温标；在所有检查通过前不更新 session。
- 当前有未保存改动时，使用一次明确的覆盖当前查看状态确认；拒绝确认即保持原状。替代原来依赖第二次按钮点击的隐式加载流程，避免第二次弹框选到不同文件。
- 读取/核验失败时显示原因及文件路径，保留原视图、范围、温标和脏状态。
- 成功后显示所加载文件名和路径；保留现有 schema v1 读取及 v2 写入兼容性。

### 4.3 边界与职责

- 文件对话框和确认窗口只在 GUI 主线程运行。采用可注入的小接口，使单元测试不弹真实窗口。
- 对话框实现使用本机可用的原生窗口适配层，管理父窗口和临时 root 的释放；无可用对话框后端时报告错误，不退回无提示的固定路径覆盖。
- `SelectionStore` 提供显式配置路径的读写入口；保留既有按源文件生成默认路径的入口，避免破坏已有非 GUI 调用。
- `ViewerSession` 负责配置内容校验、应用和状态更新，不负责弹框。
- 配置写入前解析最终路径，拒绝写入 `raw` 及其子目录、源 SEQ 本身；同样检查备份目标，不通过符号链接或目录别名绕过保护。

## 5. EXP-001：子 SEQ 配套 selection

### 5.1 输出与内容

默认输出：

```text
clips/sample_clip.seq
clips/sample_clip.selection.json
```

- 即便当前变换为 identity，也导出配套配置，以保留温标和一致的加载流程。
- SEQ 仍由 FileSDK 原生提取原始帧，像素尺寸、方向和温度值不因本功能重采样。
- 配置使用既有 schema v2，源身份绑定新子文件，而不是原始输入文件。
- 子文件共 N 帧时，配置范围为 `[0, N-1]`；首末时间取子文件真实时间戳，绝对时间不重置。
- 保留已应用的完整变换和 display 设置。由于原生提取不改变空间尺寸，原变换坐标无需另作偏移。
- 配置中的 filename 使用最终子 SEQ 名称；大小、mtime、尺寸、帧数及首末时间须与最终发布文件一致，不把随机临时文件名写进去。
- 导出请求冻结候选范围、变换、温标和两个目标快照。确认摘要列出两个文件与各自覆盖状态；这些内容变化会使原确认失效。

### 5.2 两文件一致性

单个文件可原子替换，但不能将两次文件替换称为一次原子事务。本设计采用准备、保护、发布、校验及回滚流程。

1. 在任何输出写入前，校验 SEQ、配置、临时文件和恢复文件均位于允许的输出目录，且不指向源文件或 raw。
2. 提取临时 SEQ，复用现有内容验证；基于它生成并校验临时 selection。SEQ 重命名后再核对文件身份。
3. 两个正式目标的快照都必须与确认时一致；发现变化则停止，不覆盖外部文件。
4. 发布前建立同目录的 `<名称>.export-pending.json` 标记，记录事务状态及恢复文件路径。已有未结束标记时拒绝新导出并提示先处理，不覆盖恢复材料。
5. 对需要覆盖的旧文件使用同目录唯一恢复文件保留旧状态，再发布新文件。任一步失败时，仅回滚本次事务拥有且未被外部修改的文件；不能为恢复而覆盖新的外部改动。
6. 发布后重新核验正式 SEQ 与正式 selection 的匹配关系。两者一致且清除 pending 标记后才报告成功。
7. 普通异常尽量恢复原来的一对目标；恢复失败则保留标记和恢复材料，显示实际文件状态与路径，不假报成功，也不删除可能用于恢复的数据。

成功发布或完整回滚后，只清理本次事务拥有且未被外部修改的临时/恢复文件；完整回滚后清除 pending 标记。已验证的新文件对若仅有恢复文件清理失败，应报告清理警告并列出遗留路径，不因此回滚有效输出。pending 标记清除失败时仍不得报告完整成功。

进程退出、断电不保证两个文件同时恢复。pending 标记存在时自动加载必须拒绝套用配套配置并明确报警；不得仅因为两个正式文件存在就视为事务成功。恢复材料只供后续受控恢复，不在程序启动时无条件自动删除。

### 5.3 取消与后台执行

- 继续使用后台 worker，主线程只更新进度。
- 提取及准备阶段可取消，取消后清理本次临时文件，不改变既有正式目标。
- 发布阶段进入短暂不可取消区，界面显示“正在完成配套文件，请稍候”；已接受发布前的取消则不得继续发布。
- 错误结果须包含失败阶段与恢复材料位置，UI 恢复可操作状态。

## 6. 自动发现与恢复

- 打开一个 SEQ 时，只查找其同目录、同 stem 的 `.selection.json`，不扫描最新文件，不自动选择 `selections` 中的其他配置。
- 同名 pending 标记存在：显示未完成导出警告，保留原始视图；不得自动加载，也不得通过手动 Load 绕过对应源文件的 pending 状态。
- 没有配套配置：按现有原始视图启动。
- 配置存在且有效：核验成功后，在首次正式显示前应用范围、变换和 display，显示“已加载配套配置”及路径。
- 损坏、不匹配或不支持的配置：警告用户，不降级到其他同名/最新配置；仍能以原始视图打开 SEQ。
- 自动加载只发生在启动时，不在切帧、Reset full 或编辑过程中反复触发。
- 显式 CLI `--vmin/--vmax` 优先于配套温标，并提示温标已被命令行覆盖；该状态相对配套文件属于未保存更改。
- 显式 `--frame` 仍表示源文件帧号；配套范围包含它时定位到该帧，否则保留配套范围、定位范围首帧并提示。未提供该参数则从配套范围首帧打开。
- 严格身份核验继续包含文件名及 mtime。因此仅手工重命名/改变文件时间，可能使配置不再匹配；本轮不放宽身份核验、不提供强制加载。

## 7. 模块边界

- 布局单元：提供公共区域及模式控件几何，处理信息显示位置。
- 对话框适配单元：保存/打开路径选择、确认及取消结果，不修改 session。
- selection 存储：显式路径读写、合法性与源身份检查、单文件安全保存。
- 配套导出单元：两个目标快照、准备与发布、pending 标记和回滚管理；复用 extraction 的原生提取与验证，避免把事务堆入 GUI 回调。
- 查看器启动与 session：自动发现、配置应用、CLI 优先级、脏状态；GUI 回调只协调操作。

只拆分服务于这三项修复的职责，不引入通用插件系统或新的项目格式。

## 8. 测试与验收

### 8.1 自动化

- 布局：普通/编辑模式、长路径及错误文本、不同画布尺寸/DPI；检查可见性和包围盒，并保留真实 canvas 鼠标交互回归。
- 配置：打开/保存取消、覆盖拒绝、任意合法路径、多方案、旧版配置、损坏 JSON、身份不符、raw/源路径拒绝、目标外部变化、失败后状态不变。
- 配套：identity/旋转裁剪、单帧与多帧、子帧重编号、温标/色图、重新打开自动恢复、配置缺失时原始视图启动、损坏/不匹配/pending 警告、显式 CLI 参数优先级。
- 事务：两个目标各自的覆盖组合、确认后外部修改、取消、SDK/校验失败、发布每一步失败、回滚失败、遗留 pending。测试只使用临时模拟数据，不对真实原始文件做危险路径实验。
- 回归：完整现有测试继续通过。新行为遵循先失败测试、再实现、再验证的顺序。

### 8.2 最小真实 SEQ

使用 `raw/Rec-000366-240_09_26_37_152.seq`，验证短范围原生提取、配套配置及重新打开后变换/温标一致。输出放入临时测试目录，不覆盖正式 clips 或 selections。

每次真实数据验证在 finally/fixture 清理阶段比较源文件大小和纳秒级 mtime，即使测试失败也检查。整轮回归前后核对三份 raw SEQ 的大小与 mtime。大 SEQ 不做全量载入或自动长时验证，由用户手动验收性能。

### 8.3 用户验收与发布

先验收编辑界面无重叠，再验收两套配置的保存/选择与取消，最后导出短子 SEQ、关闭并重新打开，确认自动恢复修整状态。只移动 SEQ 或移走 JSON 后，没有同名配套配置就按原始视图打开，不声称能检测已丢失的配置；同名配置仍存在但不匹配时，应明确警告且不误加载。
